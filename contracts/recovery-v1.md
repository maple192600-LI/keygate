# 离线授权修复合同 v1

本合同补齐既有商业授权的本机保护与离线校时恢复，不改变许可载荷、版本规则或到期日。厂商端和客户端共用既有 Ed25519 签发身份，修复使用独立签名域。它不授予会计权限，不签发新商业许可。

## 本机保护

普通状态保存于安装资料的 licensing/state-v2.json；独立检查点保存在当前 Windows 用户 LocalAppData/SnailFinance/license-protection 下，由数据根的摘要隔离。Windows 原生凭据保存稳定安装标识、签发公钥标识、检查点摘要和修复代次。财务账套备份不包括这些安装保护记录。

已初始化安装缺少状态、原生保护记录与状态摘要不符，均进入 LICENSE_PROTECTION_INCOMPLETE，不能按空历史初始化或接受旧版本；已有登录、查看、打印、导出与财务备份权限保持原合同。独立检查点可用于厂商签名修复，不能因文件丢失自动清空版本或时间下限。原生记录丢失或从既有 v2 升级、尚无新增独立副本时，可对现存结构与全部签名原件校验后建立 repairRequired 检查点，仅供导出厂商修复申请，普通使用与导入继续阻断；厂商签名确认后才初始化保护。保留全部已知版本和原期限，不静默重新激活。所有可信原件均丢失时保留阻断，须找回可信资料，不推测未知版本；不能证明升级前已经被移除的未知历史。

文件替换先发布普通状态，再写独立检查点并提交原生摘要。跨提交崩溃可能进入待修复；修复合并已发布且验签通过的新原件，不回退到旧版本。未完成提交的额外检查点不作为正常许可。此机制处理正常安装的单点丢失与较早副本，不承诺对抗完全控制操作系统及修改程序。

## 修复申请与签名文件

申请仍以 .snailreq 传递，UTF-8、最多 64 KiB，严格拒绝重复键、未知字段、非法编码与过深结构。字段顺序与固定向量一致：

| 字段 | 规则 |
| --- | --- |
| formatVersion / kind | 1 / license-recovery-request |
| productId | cn.snailfinance.desktop |
| requestId / installationId / challenge | UUID v4；申请、安装与独立一次挑战 |
| device | 既有 Windows 机器摘要合同 |
| stateFingerprint | 已接受原件摘要集合的 SHA-256；普通时间检查点和自动生效不改变该集合 |
| appVersion | 与客户桌面发行版本一致 |
| protectedWallMs | 当前受保护时间下限，安全非负整数 |

厂商已认证管理账号在原签发身份解锁后确认系统时间，签发 .snailrepair 并记录审计。签名正文依次为 formatVersion、kind、productId、recoveryId、requestId、installationId、challenge、binding、stateFingerprint、baselineAt、expiresAt、keyId；kind 为 license-recovery，baselineAt 为厂商确认的当前 UTC 毫秒时间，expiresAt 为其后七日，均固定 UTC 毫秒格式。

外层为 formatVersion=1、kind=license-recovery、keyId、payloadB64、signatureB64。签名对象为 UTF8(stq-license-recovery/v1) + 0x00 + 原始正文 UTF-8 字节；不得与 stq-license/v2 或资源签名混用。编码和公钥身份沿现行 v2 规则，正文最多 128 KiB，文件不自带可信公钥。

## 导入与失败保护

客户端验证签名、产品、设备、安装、申请与挑战、已接受原件集合；同一挑战只能成功一次。新许可被接受后旧申请失效，普通轮询不会使申请失效。导入时系统时间不得早于厂商时间加既有五分钟容差，且必须早于修复文件截止。校时只重设时间下限和进程单调计时起点，保留全部已接受原件、最高版本和每份许可的原到期日；到期许可仍按原截止进入只读。失败保留原许可和财务资料。

修复事件先原子保存于独立目录，记录操作者、时间、申请、修复文件摘要和前后状态摘要，并以前一事件引用形成链；只有 Windows 原生记录锚定的事件视为已应用，未锚定准备文件不作成功依据。原生摘要与事件引用一起提交；普通状态更新保留事件引用。数据库审计提交失败时明确返回修复已保存、审计提交未确认，不能当作未执行重试。下一次状态或操作记录读取按恢复标识幂等补入既有 local_user_audit；事件缺失或摘要错误保守阻断。

普通有效性与每个新业务事务实时判断。时间检查点间隔最多五分钟，导入和修复立即持久化；已准入的单个原子事务可完成，同一请求的下一事务必须重新准入。普通状态展示不取得无必要的主库写锁。

## 管理端恢复与身份连续性

签发公钥一经登记，即使签发数量为零也约束创建、预览、确认、解锁、业务数据包及备份恢复。缺少原容器时只能导入原身份。

完整恢复确认在既有写门禁内重新比较当前全部 (licenseId, revision, issuanceId, SHA-256) 原件事实；候选缺失或冲突时拒绝切换，预览后新签发同样受保护。最新可信备份可继续高于已发版本签发。新电脑仅有较早备份且没有后续证据时，离线软件无法推知未知事实；必须取得最新备份及移交资料，不能宣称较早备份已证明完整，不使用任意加大版本号的办法。

## 验收

固定 TEST_ONLY.recovery.json 与既有 RFC 8032 测试公钥用于 Go/Node 原字节互验，禁止纳入正式发行信任。直接回归覆盖丢失、损坏、旧副本、误快一天/一年、到期不续期、重放/错设备/新许可后失效、跨提交崩溃、跨到期文书事务及续期接续。真实 Electron、Go/PostgreSQL、最终安装候选的证据分别记录。
