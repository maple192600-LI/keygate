# 小云雀客户授权中心：本地运行说明

当前文档对应原生 Windows 管理客户端源码。正式交付目录、安装包哈希与验收状态以最终交付记录为准；当前不是已发布版本。

## 打开管理端

“启动管理端.bat”打开管理窗口；首次启动时另起独立后台服务进程和随包提供的 PostgreSQL。关闭管理窗口只退出操作界面，服务和数据库继续运行；重新打开时连接到已有服务。用“停止后台服务.bat”才会停止服务和数据库。无需 Docker，也无需另装 Go、Node 或数据库。

完整包沿用当前 Windows 用户 `%APPDATA%\SnailLicenseCenter` 下的受保护资料目录，升级程序时保留该目录。开发和验收可用 `SNAIL_MANAGER_DATA_ROOT` 指定隔离资料目录，不应指向现用安装。

需在用户登录 Windows 后自动启动后台服务时，在程序目录运行 `configure-startup.ps1 -Action Install`；移除时运行 `configure-startup.ps1 -Action Remove`。此配置写入当前 Windows 用户的登录启动项，用户登录后启动服务，不是 Windows 服务控制管理器（SCM）服务，也不代表未登录前即可对外服务。仅由部署人员在确定程序位置后配置；本任务不更改现用机器的启动项。

首次打开填写管理用户名、密码、商家名称和联系方式。管理用户名用于厂商登录，与商业客户分开。已有资料不会再次开放首次设置。

首次设置后会显示一次账号恢复凭据；请当场妥善保管。登录后可在“设置 → 基本信息”重新生成，生成后旧凭据立即失效。忘记管理密码时，在登录页输入用户名、恢复凭据和新密码；成功后该凭据作废并撤销旧会话。

客户、授权码、期限、设备和操作记录保存在本地数据库中。管理窗口关闭、服务重启和正常升级继续使用原资料。当前服务只绑定本机地址；固定 HTTPS 域名及公网入口尚未配置，需待部署参数和证书确定后接入。本机健康检查不能证明互联网可达。

## 授权服务身份

首次空白实例由服务自动创建并保护签发身份。若迁移已有的旧版身份，进入“设置 → 服务”，输入原签发密码一次并选择“启用自动签发”；此步骤将同一身份改为由运行资料中的加密密钥保护，不改变身份编号。之后日常发放、续费和换机不再输入签发密码，也不会因一段时间未签发而锁定。

“设置 → 服务”显示实际服务和数据库健康状态。发行公钥用于构建客户安装包，可以公开；服务私密签发身份只留在服务端。完整加密备份包含恢复签发所需的运行加密密钥和身份材料。旧身份迁移密码只用于一次迁移，不是日常密码。

正式客户安装包必须信任自己的正式签发身份。设计包里的 TEST_ONLY 公钥、演示授权和原型下载文件不能用于正式激活。

## 新建客户与发放授权

1. 在“客户”中新建客户，填写名称和实际联系方式，按需记录来源。同名客户按各自稳定编号区分，名称不会合并记录。
2. 在客户档案点击“发放授权”，选择正整数天数、月数、年数、指定到期日或永久；可默认从首次成功激活起算，也可指定生效日期。设备数可设置为任意正整数，默认1台。
3. 预览期限和生效条件后确认。系统在原客户记录下生成授权码，复制给客户。无需客户申请文件、设备码、授权文件下载或签发密码。

客户在“小团雀”授权激活界面粘贴授权码并在线激活；本管理端不收集账套或财务资料。首次激活成功时服务端固定默认期限起点。未激活时管理端显示“未激活／首次激活后N天、月或年”，不编造到期日。

签发结果暂时不明时，按原操作号查询或重试，不重复生成另一授权码。

## 续费与换机

- **续费**：在原授权详情选择续费。未到期时从当前截止时间增加所选时长；已到期时从本次办理时刻起算。预览显示原期限与新期限，不能将已有期限意外缩短。
- **换机**：在原授权详情选择当前绑定设备并填写原因。系统释放旧设备席位，保留授权编号、授权码和期限；新电脑使用同一授权码激活。换机不提供实时离线撤销。
- 授权期限状态与设备绑定状态分开显示。设备版本、构建和上报时间代表最近一次报告，不是实时监控。

授权截止时间为排他边界：到达所示截止时刻即到期。到期的已初始化客户仍可按原权限登录、查看、打印、导出和备份；新增或修改业务结果需要续期。已经进入事务的原子业务会完成，下一个新事务重新检查。

## 两种资料文件

| 操作 | 文件 | 用途 | 是否包含登录账号和签发私钥 |
| --- | --- | --- | --- |
| 导出管理数据 | `.snailbundle` | 把商业客户、授权、设备、激活码和相关记录移交给空白新实例 | 使用单独的移交包密码加密；不含登录账号、登录密码或签发私钥 |
| 备份资料 | `.snailbackup` | 恢复客户、授权、设备、管理账号、运行加密配置及签发身份 | 整体由独立备份密码加密，始终包含恢复授权服务所需的加密身份 |

在“设置 → 备份与数据”页面操作。导出管理数据时设置10至128字符的移交包密码；导入时输入同一密码预览，再用目标实例当前管理密码确认。这个密码只加密本次移交文件，不是登录或日常签发密码。文件是加密封套，不能按明文JSON查看。生成完整文件后再显示成功；失败时已有资料保留。文件大小上限为128 MiB，当前格式只接受本程序支持的版本。

备份和移交仅在需要保管副本、搬迁或恢复资料时使用，不是日常操作或普通升级的前置步骤。备份密码用于加密备份文件，需与备份分开保管。

## 恢复完整备份

1. 用当前管理账号登录，选择“恢复备份”，选择文件并输入备份密码。
2. 系统在独立数据库和目录验证文件、数据库版本、关联、数量、原件摘要及签名，显示预览。此时当前资料没有被替换。
3. 核对后输入当前管理密码，确认恢复。
4. 使用备份中保存的管理账号和密码重新登录。如果备份之后改过管理密码，恢复后使用备份时的密码。

恢复会撤销旧会话和备份中的刷新令牌，并切换到经过验证的资料。原数据库和原身份文件保留，不先清空原库。恢复完整备份后沿用原授权服务身份，可继续处理相同授权。

恢复备份要求当前管理账号登录，并重新验证管理密码。账号恢复凭据用于忘记密码，不替代资料备份；完整备份则用于恢复数据库和原服务签发身份。

## 移交给空白新实例

完整搬迁客户、授权服务、管理账号和原签发身份时，优先在目标实例恢复 `.snailbackup`。若只把业务记录导入一个已初始化的空白实例，可使用 `.snailbundle`：输入移交包密码预览并核对客户、授权、激活码和映射，再输入目标实例当前管理密码确认。业务移交包不含私钥或原厂商管理账号，不替代完整备份；未恢复原签发身份时，不能据此宣称完成了原授权服务的完整搬迁。

产品按稳定合同代码映射，计划按对应产品的固定代码和定义核对。存在冲突就拒绝，不按展示名称猜测。移交后核对客户、授权编号、原授权码、设备及期限；客户信任的公钥必须与目标服务使用的签发身份一致。

后台自身替换不改变客户已经持有的文件。更换根公钥或合同需要先部署支持它的客户端，旧客户端不会自动信任陌生身份。

## 许可与资料保护

本程序基于 Keygate，保留上游 LICENSE、NOTICE 和可见的 Powered by Keygate 署名。客户安装包与管理端为两个交付物；只把客户安装包和对应授权文件交给客户。

旧签发密码只在迁移时提交给本机服务；备份密码只用于创建或恢复备份，不进入日志或浏览器持久存储。运行中的服务和浏览器使用垃圾回收，不能承诺内存中所有临时副本都被彻底擦除。

管理密码和备份密码使用现有账号与备份规则验证，无需向开发者提供密码。
