# 蜗牛客户与授权中心：本地操作说明

当前文档对应原生 Windows 管理客户端源码。正式交付目录、安装包哈希与验收状态以最终交付记录为准；当前不是已发布版本。

## 打开管理端

独立管理客户端自动启动本地服务和随包提供的 PostgreSQL，关闭窗口后自动关闭本次服务和数据库。无需 Docker，也无需另装 Go、Node 或数据库。软件使用当前 Windows 用户的受保护资料目录，升级程序时保留该目录。

首次打开填写管理用户名、密码、商家名称和联系方式。管理用户名用于厂商登录，与商业客户分开。已有资料不会再次开放首次设置。

客户、授权版本、签发原件、设备和交付记录均由程序自动保存在本地数据库中，关闭重开和正常升级继续使用原资料。日常发放及续期不需要导出管理备份或重新导入签发身份；客户正常升级不需要重新申请、补签或重导授权。

## 准备签发身份

进入“设置 → 签发身份”。首次使用选择“创建签发身份”，输入当前管理密码并设置签发密码。后续安装、升级和移交使用原身份，不能随意换成新身份。管理端会阻止已有签发历史的实例新建另一身份。

签发身份就绪后，可导出发行公钥和备份签发身份。发行公钥用于构建客户安装包，可以公开；加密签发身份只在厂商控制的位置保存，不交给客户。签发密码不写进备份文件或登录资料。手动锁定、退出管理会话或15分钟无签发活动后，需要重新解锁。

正式客户安装包必须信任自己的正式签发身份。设计包里的 TEST_ONLY 公钥、演示授权和原型下载文件不能用于正式激活。

## 新建客户与发放授权

1. 在“客户”中新建客户，填写名称和联系方式或邮箱，按需记录来源。没有邮箱可以正常建客户和发证，不必编造邮箱。
2. 客户在蜗牛财务激活页导出这台电脑的申请文件，交给厂商。
3. 在客户档案点击“为此客户发放授权”，导入申请文件，也可填写完整设备码。选择天、月、年或永久期限，核对预览后确认签发。
4. 下载授权文件，复制交付说明，通过双方约定的方式交付。软件不会自动发送。
5. 实际交付后，登记交付方式、收件对象和交付时间。下载文件不会自动变成“已交付”。

客户导入正确授权文件后，才能创建这台电脑的首位管理员。授权跟随产品和设备，不跟随某个本机管理员。

签发结果暂时不明时，使用原操作恢复结果，不重新发起另一份授权。系统按原操作号返回同一版本和同一文件原字节。

## 续期、换机和停发

- **续期**：在授权详情选择续期。未到期授权从现有截止时间继续增加，到期后从本次签发基准时间重新计算。永久授权不能再增加期限。
- **换机**：取得新电脑的申请，选择换机并填写原因。换机保留原授权编号和原截止时间，产生新版本，历史设备和文件继续保留。
- **停止续发**：阻止后续签发，不会远程立即注销客户已经持有的离线文件。恢复续发后可继续办理。
- **期限、交付、续发状态**分别显示。没有使用回传时显示“未回传”，不能据此判断客户已导入或最近使用。

授权截止时间为排他边界：到达所示截止时刻即到期。到期的已初始化客户仍可按原权限登录、查看、打印、导出和备份；新增或修改业务结果需要续期。已经进入事务的原子业务会完成，下一个新事务重新检查。

## 两种资料文件

| 操作 | 文件 | 用途 | 是否包含登录账号和签发私钥 |
| --- | --- | --- | --- |
| 导出管理数据 | `.snailbundle` | 把商业客户、授权、设备、申请、各版原件、交付和必要操作记录移交给空白新实例 | 不含登录账号、登录密码、刷新令牌或私钥；包含公开身份 |
| 备份资料 | `.snailbackup` | 恢复数据库、管理账号和配套运行加密配置 | 整体由独立备份密码加密；勾选并确认时包含加密签发身份 |

在“设置 → 备份与数据”操作。生成完整文件后再显示成功；失败时已有资料保留。文件大小上限为128 MiB，当前格式只接受本程序支持的版本。

备份和移交仅在需要保管副本、换电脑或处理资料故障时使用，不是日常操作或普通升级的前置步骤。“设置 → 签发身份 → 处理客户授权故障”只用于真实授权损坏或校时异常；当前管理登录有效且签发身份已解锁时，直接选择申请并点击“生成并保存修复文件”，无需再输入管理登录密码。

## 恢复完整备份

1. 用当前管理账号登录，选择“恢复备份”，选择文件并输入备份密码。
2. 系统在独立数据库和目录验证文件、数据库版本、关联、数量、原件摘要及签名，显示预览。此时当前资料没有被替换。
3. 核对后输入当前管理密码，确认恢复。
4. 使用备份中保存的管理账号和密码重新登录。如果备份之后改过管理密码，恢复后使用备份时的密码。

恢复会撤销旧会话和备份中的刷新令牌，并切换到经过验证的资料。原数据库和原身份文件保留，不先清空原库。关闭重开后仍使用恢复后的数据库。未包含加密签发身份的备份需要另外导入同一签发身份，才能继续签发。

本入口要求当前已登录的管理员。忘记管理密码时由开发人员在用户控制的本机资料上协助恢复访问，不能重新首次设置覆盖原账号。丢失签发密码时，无法从不可解密的身份容器恢复私钥。

## 移交给空白新实例

1. 原管理端导出管理数据包，并单独备份加密签发身份。
2. 新实例先完成自己的管理账号初始化。商业客户、申请、授权、签发、交付必须为空；不支持合并两个已有客户库。
3. 选择“导入管理数据”，验证并预览数量、签发身份及产品和计划映射，再输入新实例的管理密码确认。
4. 产品按稳定合同代码映射，计划按对应产品的固定代码和定义核对。存在冲突就拒绝，不按展示名称猜测。
5. 在“签发身份”单独导入原加密身份，核对历史匹配并解锁。业务数据导入不会自动导入私钥，也不会导入原厂商的登录账号。
6. 核对原件和最高版本后继续续期。原客户安装包仍使用原公钥和v2合同验证文件。

后台自身替换不改变客户已经持有的文件。更换根公钥或合同需要先部署支持它的客户端，旧客户端不会自动信任陌生身份。

## 许可与资料保护

本程序基于 Keygate，保留上游 LICENSE、NOTICE 和可见的 Powered by Keygate 署名。客户安装包与管理端为两个交付物；只把客户安装包和对应授权文件交给客户。

签发密码和备份密码只用于当前操作，不进入日志或浏览器持久存储。运行中的 Go 和浏览器使用垃圾回收，不能承诺内存中所有临时副本都被彻底擦除。

管理密码、签发密码和备份密码使用10到128个字符。汉字、字母、数字和标点都能使用，无需向开发者提供密码。

版本0.1.1：概览、授权列表中的“发放授权”会先选择客户，也可直接新建客户后继续发放。交付记录默认显示全部当前原件；从概览的待交付卡进入时只显示待交付。可在列表直接下载原件，下载不会登记交付。
