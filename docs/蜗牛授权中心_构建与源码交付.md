# 独立 Windows 管理包

本期按用户明确要求使用独立 Electron 客户端，无 Docker。独立后台宿主管理一个 Go 服务和一个原生 PostgreSQL 17.11 进程；管理窗口关闭后它们继续运行。默认监听本机回环地址，管理入口与客户激活／同步入口分开。网页出现前先生成数据库、会话和运行加密秘密。HTTPS 外部入口仅预留部署配置，当前不要求域名或公网部署。

运行依赖随管理 ZIP 一起提供。解压到普通目录后双击 `run.bat` 或“小团雀客户授权中心.exe”；`stop.bat` 请求当前实例正常关闭，等待 Go 退出后关闭数据库，不强杀或清空资料。只启动停止入口时不会初始化数据库。管理资料位于当前 Windows 用户 `%APPDATA%/SnailLicenseCenter`，重装/升级时保留该目录。源代码运行要求明确指定隔离数据目录；正式包默认使用固定资料目录，部署隔离使用明确的 `SNAIL_MANAGER_DATA_ROOT`。

## 固定构建入口

源码采用官方 Keygate 基线 ed141b6b29bd4c5e6a45f5cb36e757458da7af72，衍生改动保持 AGPL-3.0 与 NOTICE，界面保留 Powered by Keygate。交付同时附带本次候选的源码 ZIP、此构建说明、Go/Bun/npm 锁文件及上游许可。源码包不含运行资料或签发私钥。

随附源码 ZIP 用于读取对应源码，不含 Git 元数据。正式重建从仓库 `https://github.com/maple192600-LI/keygate` 获取 Git 检出，固定到随包 `管理包验收身份.json` 的 `candidate` 字段；同一值也在展开包的 `源码与许可.txt`。在全新目录执行：

```powershell
$delivery = Get-Content -LiteralPath '交付目录\管理包验收身份.json' -Raw | ConvertFrom-Json
git clone https://github.com/maple192600-LI/keygate.git snail-license-center-source
Set-Location snail-license-center-source
git checkout --detach $delivery.candidate
git rev-parse HEAD
git status --porcelain
```

核对 HEAD 与交付清单一致且工作区干净，然后使用该检出执行以下构建步骤。私有仓库需要已有读取权限。不能在源码 ZIP 内随意 `git init` 后用新提交冒充原候选。

构建人员使用 Windows x64、Go 1.27.3、Bun 1.4.4、Node 24.18.0；管理客户端使用锁文件中的 Electron 43.7.0 和 electron-builder 26.15.3。先在 `desktop` 执行 `npm ci`，再设置以下完整路径并执行 `npm run package`：

| 变量 | 内容 |
| --- | --- |
| SNAIL_GO_EXECUTABLE | Go 编译器 go.exe |
| SNAIL_BUN_EXECUTABLE | Bun 构建工具 bun.exe |
| SNAIL_POSTGRES_RUNTIME | PostgreSQL 17.11 解压根，含 bin、lib、share、server_license.txt、commandlinetools_3rd_party_licenses.txt |
| SNAIL_MSVC_RUNTIME | 固定清单对应的 Visual Studio 2022 x64 可再发行 CRT，dlls 子目录与微软原始许可 |
| SNAIL_MANAGER_OUTPUT | 本次全新空交付目录 |

打包入口要求干净已提交候选，直接编译 Go、冻结安装及构建中文本地网页，再打包管理客户端和原生 PostgreSQL。输出包含 ZIP、展开目录和产物哈希记录。已有输出不被覆盖。开发和正式私钥、数据库、签发身份容器、TEST_ONLY 合同样本不进入管理运行包。

PostgreSQL 官方 Windows 分发来自 EDB 的 postgresql-17.11-1-windows-x64-binaries.zip，只携带 bin/lib/share 及对应许可证，不安装 pgAdmin、StackBuilder 或系统数据库服务。开发资料中记录的压缩包 SHA-256 是本轮下载值，未冒充独立厂商公布校验值。

全新 Windows 验证实际发现 EDB 数据库程序依赖 MSVCP140/VCRUNTIME140，系统未安装时退出 0xC0000135。包内在数据库程序同目录放置本机 Visual Studio 2022 Community 的 VC/Redist 正式 x64 CRT 文件，按 native-runtime.lock.json 核对未修改的 DLL 字节；保留微软原始许可。采用[微软支持的应用本地目录部署](https://learn.microsoft.com/en-us/cpp/windows/redistributing-visual-cpp-files)，依照[VS2022 可再发行清单](https://learn.microsoft.com/en-us/visualstudio/releases/2022/redistribution)，不复制系统目录 DLL、不执行系统运行库安装，不让使用者搭建环境。运行库版本随管理包维护升级，不能把本地部署描述为会自动收到系统运行库更新。

## 验收状态

源代码、开发窗口、展开包和正式安装包分别记录。构建成功只证明产物形成，实际运行/安装、双设备许可及正式签发身份尚须取得各自的验收证据；不得据本说明提前宣布已发布。


管理包运行验证续记：新 Windows 沙盒确实缺少 MSVC 运行库，原生数据库程序返回0xC0000135。固定 VS2022 CRT 原文件随包后，三个数据库程序均返回0。初始化捕获输出时包内启动未返回，现改为30秒上限和 initialization.log 文件输出，实际已走到健康身份校验与 window-loaded。尚未细化到具体句柄继承进程，不把全部失败归因于运行库。

实际包UI已完成首次设置、无邮箱客户、签发身份与签发原件。原失败样本漏填联系入口，产品正确拒绝；测试调用BAT引号已纠正。随后实际Windows报BAT中的命令片段无法识别，核对包内为LF文本，构建现明确转换Windows CRLF，继续做真实BAT启动停止和重开验证。该节点仍未标为管理包通过。

中文路径实测：bbdb26a包放到中文且含空格的目录后，PostgreSQL初始化明确报 invalid byte sequence for encoding UTF8。原程序和数据不搬移，原生启动器仅在受当前Windows用户保护的 ProgramData/SnailLicenseCenter-用户SID 中建立英文目录junction，分别指向包内PostgreSQL和原AppData资料。初始化、数据库进程和PG日志参数使用这些英文别名。未知占用不清除，资料链接不符即拒绝；升级只重新连接程序别名，保留原目录。仍需实际Windows包复验。

独立审查纠正：首版可预测SID目录会保留预占者的显式ACE，确认为P1，未采用。现每次启动使用随机128位名称，Windows Directory.CreateDirectory(path,DirectorySecurity) 在创建时指定当前SID的私有受保护DACL；事前拒绝任何已有对象，事后核对所有者、DACL保护状态和唯一当前SID完全控制。Go与数据库正常停止后，只验证并移除本次两条junction及空目录，不跟随到原程序和资料；未知对象或改变的链接保留并报告。启动失败时保留映射用于定位，不扫描或删除其他运行残留。

定向 node --test desktop/runtime.spec.cjs：3/3通过；实际测试预占路径加Everyone显式完全控制后，创建被拒且ACL与原文件均未改变；正常释放保留真实源文件，未知对象/改变的资料链接拒绝清理。首次ACL核验使用Get-Acl遭遇本机PowerShell模块自动加载失败，已改用同一Windows .NET Directory.GetAccessControl，不更改执行策略或模块配置。该节点仍等待实际包复验和独立复审。

P2退出整改：辅助映射清理失败现返回NATIVE_MAPPING_RETAINED告警，保留目录；仅在Go和PG均已停止后，窗口提示保留位置并允许最终退出。真正服务/数据库停止失败仍阻止退出并报告。新增 node --test desktop/native-paths.spec.cjs 在本任务中文程序/资料路径实际启动Go和独立PG，注入辅助未知文件后验证HTTP关闭、PG status=3、无postmaster.pid、未知文件字节保留、重复stop仍返回告警而非抛错；1/1通过（3.96秒）。本次独占测试目录和链接随后核对归属并清理，外部PG工具保持。该测试证明原生运行关闭合同；异常提示框的包内人工确认尚未实测。
